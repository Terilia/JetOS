## Critical bugs (hand-verified)

### ☑ 1. Selecting a target silently destroys saved configuration
`Utilities\CustomDataManager.cs:43` + `Utilities\Shortcuts.cs:90`

Config lines are saved as `Config:altitude_warning:150`, but `ParseCustomData` keys on the **first** colon, so
every config line collapses into the single cache key `"Config"`. Any `SetCustomDataValue` call (happens every
tick a target is selected, via `UpdateActiveTargetGPS`) triggers `RebuildCustomData`, which rewrites CustomData
from the cache — leaving exactly **one** surviving config line. In-memory values mask the loss until
recompile/world reload, then everything resets to defaults. Colon-less lines (user notes) are also dropped.

**Fix**: change `CD_CONFIG` from `"Config:"` to `"Config_"` — keys become unique, both ConfigurationModule
parse paths still work (`Substring(CD_CONFIG.Length).Split(':')` yields 2 parts). One-time reset of previously
saved settings. Size: neutral (1 char).

### ☑ 2. Docking corrupts the grid silhouette and can blow the instruction budget
`UI\GridVisualization.cs:103`

Rebuild phase 1 collects `IMyTerminalBlock` with no `IsSameConstructAs` filter, so docking to a
carrier/station pulls in every connected grid's blocks: garbage occupancy map (`b.Position` is per-grid local),
permanently poisoned `originalBlockCount` (latched at first nonzero), and phase 2 doing per-block `GetCubeBlock`
over thousands of station blocks in one tick — real risk of exceeding the 50K instruction budget and killing
the PB.

**Fix**: `program.GridTerminalSystem.GetBlocksOfType<IMyTerminalBlock>(gridBlocks, b => b.IsSameConstructAs(program.Me))`.
Merge-attached missiles are same-construct, so bay accounting survives. Size: ~+45 chars.

### ☑ 3. The documented 60s selected-target decay doesn't exist
`Jet.cs:443` (vs CLAUDE.md "Target Data Flow")

CLAUDE.md documents `SELECTED_DECAY_SECONDS = 60`, but commit `750988b` deleted it — every contact decays at
30s, selected or not (the loop still computes `isSelected`, now only to `ClearSelection()`). Knock-on:
`EnemyContact.IsStale` (30s threshold, same as removal) is true for ≤1s before the decay sweep deletes the
contact, so all four "stale contact" render paths (`WeaponScreenRenderer.cs:122,253`, `TerrainModule.cs:367`,
`RadarControlModuleV2.cs:197`) are effectively dead code.

**Fix (decision needed)**: either restore the 60s selected tier (~+80 chars), or bless the flattening and
delete the `IsStale` property + its consumers (**net shrink**) and correct CLAUDE.md.

## High-confidence bugs (agent-verified)

- ☑ **Double-Main guard misses `UpdateType.Terminal`** — `SystemManager.cs:164`. Running with an argument from
  the terminal panel double-ticks everything in one sim frame; the `dt≤0 → 1/60` clamp over-advances time.
  Fix: `(updateSource & (UpdateType.Trigger | UpdateType.Terminal)) != 0`. ~+25 chars.
- ☑ **AB thruster overrides never reset** — `Modules\HUDModule.cs:604`. Leaving afterburner disables the tanks
  but leaves hydro thrusters at 100% override; any other H2 source (O2/H2 gen, refuel after docking) = surprise
  full afterburner. Fix: `else` branch zeroing the AB group override (change-tolerance makes the repeated call
  free). ~+80 chars.
- ☑ **Canards freeze at last deflection when damping disabled** — `Modules\CanardModule.cs:53`. The disable
  path restores stabs but never zeroes canard trim — toggle off mid-maneuver and they stick (up to ±45°).
  Fix: `SetCanards(0, 0)` in the inactive branch. ~+25 chars.
- ☑ **SoundManager: one-shot cooldowns latch without the sound playing** — `Utilities\SoundManager.cs:82,194`.
  A request that wins the priority race but lands mid-transition (6–9 tick window) is swallowed while its
  cooldown arms — BINGO locked out 30s, engine-fire warnings 12s, unheard. Also `requestedLoopSeconds` can be
  overwritten mid-transition, so the playing clip inherits the wrong loop interval. Both fixable as pure field
  plumbing **without touching the 3-tick state machine** (latch cooldown where `pendingSound` commits; copy
  loop-seconds into a pending field at the same moment). ~+150–200 chars total.
- ☑ **Lock flicker in plugin-feed mode** — `Modules\RadarControlModuleV2.cs:115-124`. With `JetOSRadarFeed`
  present, the early return skips the entityId rescue, so `IsTrackLocked` rests on a 50m proximity test that
  fast targets break between feed updates. Fix: move the entityId check before the early return. Neutral.
- ☑ **DatalinkV2 trio** — `Utilities\DatalinkV2.cs`: `_sent` list never pruned (unbounded growth + linear scan
  per send attempt every 0.2s; fix: `Prune(_sent, ...)` in `Tick()`, ~+50 chars); status word reports bay
  *blocks* not loaded missiles (`:227` — count `IsConnected` instead, ~+70 chars); local contacts broadcast
  `age=0` when up to 3s stale (`:77-86` — pass `c.AgeSeconds`, ~+20 chars).
- ☑ **Energy carat doubly dead** — `Modules\HUDModule.cs:296` + `HUD\InstrumentRenderer.cs:260`.
  `previousVelocity` is updated before render so acceleration is always zero; and `Length()` is non-negative so
  the "E−" branch is unreachable anyway. Fix: store signed energy rate in `UpdateFlightData`, pass it through.
  Roughly neutral.
- ☑ **Asin NaN edges** — `Modules\HUDModule.cs:442` (straight up/down) and `Utilities\TerrainData.cs:147/174/191`
  (poles). Normalized dot can drift past 1.0 by 1 ulp → NaN sprites for a tick / wrong-hemisphere row index.
  Fix: clamp to [−1,1]. ~+10 chars per site.
- ☑ **Contact-tracking details** — `Jet.cs:364-373`: accel EMA silently zeroed when a contact updates twice in
  one tick (STT + IGC feed overlap, `dt==0` path) — carry the previous EMA instead of `VZ` (~+40 chars).
  `Jet.cs:66` vs `:418`: new/re-acquired contacts get a fully-green 30s `TrackHistory` (ctor all-ones
  contradicts the "start fresh with 1" comment) — pick one intent (~+30 chars or comment fix).
- ☑ **Gun D-term kick on target switch** — `Modules\GunControlModule.cs:243`. `LastAimDir` persists across
  `FlipGPS`/target loss; first tick after a switch sees the full angular jump ÷ one dt — one-tick saturated RPM
  twitch. Fix: clear `HasLastAimDir` when the aim source changes. ~+80 chars.
- ☑ **TerrainData robustness** — `Utilities\TerrainData.cs:113-131`: `DownloadChunk` doesn't validate responses
  (no `'E'` check; stale payload can be written at the wrong offset). `:62-97`: `Init` is one-shot — if the mod
  isn't ready at compile time, terrain stays dead until recompile; add a retry in `Tick` when
  `!_ready && !_downloading`. ~+100–140 chars combined.
- ☑ **Config save CRLF accumulation** — `Modules\ConfigurationModule.cs:202/210`. Split on `'\n'` +
  `AppendLine` (CRLF) adds a `\r` to preserved lines each save plus growing trailing blanks. Fix:
  `.Append(line.TrimEnd('\r')).Append('\n')`. Neutral/slight shrink.
- ☑ **Ballistics epsilon mis-scaled** — `Utilities\BallisticsCalculator.cs:35`. `Ab(qA) < 1e-6` against a
  quantity of magnitude ~10⁶ — degenerate branch never fires. Harmless at current muzzle velocities; use a
  relative threshold (`1e-6 * S2`) if `gun_muzzle_velocity` is ever lowered near closure speeds. Neutral.

## Performance

### ☑ P1. `UpdateActiveTargetGPS` — per-tick CustomData rebuilds *(revised after missile-project verification)*
`SystemManager.cs:382-398` via `Modules\AirtoAir.cs:87` (background-ticked every tick)

With a target selected, every tick performs two full dictionary→string rebuilds and two assignments to
`Me.CustomData` (a replicated terminal property): one for `Cached:` (GPS), one for `CachedSpeed:`.

**Verified against the missile project** (`Terilia\missile`):
- New missiles are **IGC-primary** (`JETOS_MSL_{bay}` tuple stream from `MissileBayHelper.BroadcastTargetUpdates`),
  own-radar secondary — but **`Cached:` is a live in-flight fallback**: when there is no radar lock AND no IGC
  message that tick AND `_antiairmode` is on, the missile re-reads the jet PB's CustomData on hash change
  (`missile\Program.cs:339-364`). If the jet's antenna dies mid-flight, this path is what keeps the missile
  guided (CustomData syncs independent of antennas). **Do NOT throttle `Cached:`** — the original "throttle to
  4Hz" recommendation would degrade terminal guidance in exactly that failure mode.
- **`CachedSpeed:` is read by nothing in the new missile project** — only old-protocol missiles could consume it.

**Planned fix** (pending confirmation that no old-protocol missiles remain in service):
1. **Remove the `CachedSpeed:` write** from `UpdateActiveTargetGPS` (halves the rebuilds; net shrink). If old
   missiles might still fly, throttle it to ~1Hz instead of removing.
2. **Add an unchanged-value early-out to `CustomDataManager.SetValue`**:
   `string old; if (customDataCache.TryGetValue(key, out old) && old == value) return;` — no-ops the writes for
   `AntiAir:`/`Topdown:` flags and stationary targets. ~+70 chars.
3. In `RebuildCustomData`, assign `lastCustomDataRaw` from the built string instead of re-reading
   `programBlock.CustomData`. ~−15 chars.
4. *(Optional, bigger win)* gate the `Cached:` write on "any missile in flight OR <5s since launch" using
   `MissileBayHelper`'s fired-bay state — keeps the 60Hz fallback exactly when it matters, silent otherwise.

Net size: roughly neutral to shrink (item 1 pays for item 2).
